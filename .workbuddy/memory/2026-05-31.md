# 2026-05-31 工作日志

## V2 重构：运行时动态类型 + [EnableQuery] 正式启用

### 核心变化

**问题回顾**
- V1 用 `Dictionary<string, object?>` 存储数据，`[EnableQuery]` 无法通过反射找到属性名
- 解决方案：用 `Reflection.Emit` 在运行时生成有真实 CLR 属性的实体类

### 新增文件

**`Services/DynamicTypeBuilder.cs`**
- 使用 `AssemblyBuilder.DefineDynamicAssembly` + `ModuleBuilder.DefineType`
- 为每个实体集动态生成类型（如 `DynamicOData.Products`）
- 每个属性生成 backing field + getter/setter IL 指令
- 缓存已生成的类型（同 entitySetName 只生成一次）

### 修改文件

**`Services/DynamicEdmModelBuilder.cs`**
- 改回 `ODataConventionModelBuilder`（而非底层 EdmModel API）
- 基于运行时 CLR Type 构建 EDM，自动带上 CLR 类型注解
- `[EnableQuery]` 通过 CLR 类型注解找到正确的元素类型

**`Services/EntityDataStore.cs`**
- `LoadDataSource` 改为实例化运行时 CLR 类型（`Activator.CreateInstance`）
- 新增 `GetTypedQueryable`：用反射 `Queryable.Cast<T>()` 返回 `IQueryable<T>`
- 修复 JSON 数组/对象字段的序列化

**`Controllers/DynamicODataController.cs`**
- 移除 200 行手写 OData 查询解析器
- 恢复 `[EnableQuery]` 属性 —— 框架自动处理 $filter/$select/$orderby
- 改用 `GetTypedQueryable` 返回 `IQueryable<T>`（T=运行时 CLR 类型）

**`Program.cs`**
- 启动流程重组：Config → Schema → CLI Type → EDM Model → Load Data → DI

### 前端升级

- 安装 `odata-query` 8.1.0 库（前端 LINQ/Lambda 式 OData 查询构建）
- `useOData.ts` 改用 `buildODataQuery()` 生成查询 URL
- 前端构建通过

### 验证结果

全部 6 项测试通过：
- `$filter=Price gt 5000&$orderby=Price desc&$top=3&$count=true` ✅
- `$select=Name,Price&$top=2` ✅
- `$filter=contains(Name,'Pro')` ✅
- `$filter=Level eq 'VIP'` (Customers) ✅
- `GET /Products/1` ✅
- Orders filtering + select ✅

### 关键决策
- 方案1（运行时动态类型）成功走通，无需方案2（预生成实体类）
- `IQueryable.Cast<T>()` 是关键——让 `[EnableQuery]` 通过 `IEnumerable<T>` 找到元素类型
- `ODataConventionModelBuilder` 在运行时的 CLR 类型上工作正常
